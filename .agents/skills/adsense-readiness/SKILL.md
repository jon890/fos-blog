# AdSense 승인 준비도 진단

AdSense 거절 통보는 "가치가 별로 없는 콘텐츠" 처럼 뭉뚱그려 오기 때문에,
무엇을 고쳐야 하는지는 사이트를 직접 재서 좁혀야 한다.
이 스킬은 그 좁히기를 8축으로 나눠 수행하고 개선 순서를 제시한다.

## 이 진단의 설계 원칙

**측정 가능한 것부터 잰다.** 8축 중 5축은 스크립트로 결정적으로 판정된다.
남은 3축(독창성, E-E-A-T, 정책 위반)만 사람이나 LLM 판단이 필요하고,
그 판단조차 기계 지표로 후보를 좁힌 뒤에 적용한다.

**LLM 채점을 완료 판정에 쓰지 않는다.** 독창성을 LLM 이 매긴 점수로 관리하면
점수가 실행마다 흔들려 개선 반복이 수렴하지 않고,
더 나쁘게는 글이 판정자를 만족시키는 방향으로 최적화된다.
LLM 은 어느 글을 고칠지 고르는 데만 쓰고, 완료 조건은 "판정 후보 N개 → 0개" 처럼
재현 가능한 기계 지표로 잡는다.

## 진행 순서

### 1. 입력 확보

진단에 필요한 것은 셋이다. 없으면 사용자에게 묻는다.

| 입력 | 왜 필요한가 |
| --- | --- |
| 배포된 사이트 도메인 | 크롤·필수 페이지·얇은 페이지를 실제 응답으로 재기 위해 |
| AdSense 에 신청한 도메인 | 루트 도메인 단위로만 신청되므로, 콘텐츠 위치와 다르면 그 자체가 원인이 된다 |
| 콘텐츠 원본 디렉터리 (있으면) | 마크다운 원본이 있으면 분량·독창성을 훨씬 정확히 잰다 |

**거절 통보 문구가 있으면 반드시 받아 둔다.** 어느 축부터 볼지가 문구로 갈린다.

| 통보 문구 | 우선 볼 축 |
| --- | --- |
| 가치가 별로 없는 콘텐츠 / low value content | 축 1, 2, 3 |
| 사이트를 이용할 수 없음 / 사이트 다운 | 축 5, 6 |
| 정책 위반 | 축 8 |
| 사이트 탐색 불가 | 축 4, 5 |

문구가 없으면 8축을 모두 돌린다.

### 2. 결정적 검사 실행

네 스크립트가 6축을 덮는다. 인자만 바꿔 어느 사이트에나 쓴다.
결정적으로 판정되는 5축(1·2·4·5·6)에 축 7 의 메타데이터 측정이 더해진다.

명령은 **스킬 디렉터리에서** 실행한다. 다른 위치에서 부를 때는 경로를 앞에 붙인다.

```bash
# 축 1·3 — 콘텐츠 원본이 있을 때
python3 scripts/content_audit.py --root <마크다운 디렉터리> --json

# 축 4·5·6 — 배포된 사이트
python3 scripts/site_audit.py --domain <콘텐츠 도메인> --apply-domain <신청 도메인> --json

# 축 2 — 색인 대상 중 얇은 페이지
python3 scripts/thin_page_audit.py --sitemap https://<도메인>/sitemap.xml --json

# 축 7 — 렌더된 페이지의 저자·작성일·구조화 데이터
python3 scripts/metadata_audit.py --sitemap https://<도메인>/sitemap.xml --path-prefix /posts/ --json
```

`--json` 없이 실행하면 사람이 읽기 좋은 요약이 나온다. 사용자에게 보여줄 때 유용하다.

콘텐츠 원본이 없으면 축 1·3 은 `thin_page_audit.py` 결과와 표본 열람으로 대신한다.

**원본이 아니라 렌더 결과로 판정한다.** 이 원칙이 축 7 에서 특히 중요하다.
콘텐츠 원본에 저자와 작성일이 없어도 사이트가 다른 출처로 노출하고 있을 수 있어,
원본만 보면 멀쩡한 사이트를 결함으로 오진한다.
같은 이유로 응답 코드만 보고 판정하지 않는다 —
서로 다른 URL 이 모두 200 을 반환해도 내용이 다를 수 있다.

### 3. 판정과 등급

각 축을 세 등급으로 나눈다. 등급 기준은 [`references/axes.md`](references/axes.md) 에 있다.

- **차단** — 이대로 신청하면 거절될 가능성이 높다
- **주의** — 심사 표본에 걸리면 불리하게 작용한다
- **통과** — 이 축은 문제없다

**통과한 축도 수치와 함께 보고한다.** "콘텐츠는 괜찮다" 보다
"산문 중앙값 4,529자, 600자 미만 0.3%" 처럼 적는 편이 다음 판단에 쓸모 있고,
개선 후 재측정할 때 비교 기준이 된다.

### 4. 좁혀진 표본만 판정

`content_audit.py` 가 `judgment_candidates` 로 내놓은 글들이 판정 대상이다.
경험 신호도 증거 신호도 없는 글이라 재서술일 가능성이 높다.

이 판정은 **작성자와 분리된 맥락에서** 한다. 글을 쓴 세션이 자기 글을 채점하면 후해진다.
판정 방법은 [`references/judging.md`](references/judging.md) 를 따른다.
핵심은 점수 대신 이진 판정을 받고 원문 인용을 강제하는 것이다.

### 5. 개선 순서 제시

축 등급과 수정 비용으로 순서를 정한다. 일반적으로 이 순서가 효율적이다.

1. **차단 등급 중 설정 변경으로 끝나는 것** — 색인 제외, robots, 리디렉션. 글을 안 고쳐도 된다
2. **차단 등급 중 콘텐츠 수정** — 얇은 글 보강, 재서술 글 개선
3. **주의 등급**

개선 후에는 같은 스크립트를 다시 돌려 수치를 비교한다.
**개선 반복의 종료 조건은 기계 지표로 잡는다** — "판정 후보 22개 → 0개",
"얇은 페이지 17개 → 0개" 처럼 재현 가능한 형태여야 개선이 실제로 일어났는지 확인된다.

## 자주 놓치는 지점

**저가치 판정은 글이 아니라 목록 페이지에서 나오는 경우가 많다.**
글 하나하나가 충실해도 카테고리·태그·목록 페이지가 sitemap 에 대량으로 실려 있으면
심사 표본이 그쪽에 걸린다. 축 2 를 축 1 보다 먼저 의심할 만하다.

**색인 제외와 sitemap 은 함께 봐야 한다.**
페이지에 `noindex` 를 걸어도 sitemap 에 남아 있으면 "색인하지 마라" 와 "여기 있다" 가 모순된다.
`thin_page_audit.py` 가 sitemap 기준으로 도는 이유가 이것이다.

**신청 도메인이 리디렉션만 한다고 그것을 원인으로 단정하지 않는다.**
콘텐츠가 서브도메인에 있고 루트가 리디렉션만 하면 심사 봇이 처음 만나는 것은 리디렉션 응답이다.
그래서 의심하기 쉬운 지점이지만, 실측에서는 봇이 리디렉션을 따라가 콘텐츠를 평가하고 있었다.
판정 순서는 [`references/axes.md`](references/axes.md) 의 축 6 을 따른다 —
콘솔의 소유권 확인이 통과면 이 축이 원인일 가능성은 낮다.

**도메인 연령과 글 수는 고치는 것이 아니라 기다리는 것이다.**
3~6개월 미만이면 다른 축이 완벽해도 떨어질 수 있다.
이 경우 개선을 반복하는 것보다 시점을 기다리는 편이 낫다는 것을 사용자에게 알린다.
다만 이 연령·글 수 기준은 공식 문서에 없는 경험칙이다 —
근거의 성격은 [`references/policy-basis.md`](references/policy-basis.md) 를 함께 읽고 판단한다.
