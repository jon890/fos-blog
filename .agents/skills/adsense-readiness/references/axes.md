# 8축 등급 기준

각 축을 **차단 / 주의 / 통과** 로 나눈다.
기준값은 절대 진리가 아니라 거절 사례에서 반복 관찰된 선이다.
경계에 걸리면 다른 축과 함께 보고 판단한다.

## 축 1 — 콘텐츠 충실도

**측정**: `content_audit.py` 의 `prose_chars`, `code_ratio_pct`, `thin_docs`

| 등급 | 기준 |
| --- | --- |
| 차단 | 글 수 20개 미만이거나, 산문 중앙값 600자 미만이거나, 600자 미만 글이 40% 초과 |
| 주의 | 산문 중앙값 600~1,200자, 또는 600자 미만 글이 15~40% |
| 통과 | 산문 중앙값 1,200자 이상이고 600자 미만 글이 15% 미만 |

**코드 비중을 따로 본다.** 크롤러는 코드 블록을 콘텐츠로 세지 않는다.
코드가 60%를 넘으면 산문 분량이 충분해도 주의로 내린다.
기술 블로그에서 흔한 함정이라 별도 지표로 둔다.

**분량을 늘리는 것이 목적이 아니다.** 얇은 글을 물타기로 늘리면
정보 밀도가 떨어져 오히려 저가치에 가까워진다.
얇은 글은 늘리기보다 합치거나 색인에서 빼는 편이 낫다.

## 축 2 — 얇은 페이지 색인

**측정**: `thin_page_audit.py` 의 `thin_count`, `by_route`

| 등급 | 기준 |
| --- | --- |
| 차단 | sitemap URL 의 25% 이상이 임계 미만 |
| 주의 | 10~25% |
| 통과 | 10% 미만 |

**`by_route` 를 반드시 본다.** 얇은 페이지가 한 라우트에 몰려 있으면
그 라우트만 색인에서 빼면 끝난다. 글을 고칠 필요가 없다.
목록·카테고리·태그·페이지네이션 라우트가 전형적인 집중 지점이다.

수정 수단은 셋이고 아래로 갈수록 강하다.

1. 해당 라우트를 sitemap 에서 제외
2. 페이지에 `robots: { index: false, follow: true }` 부여
3. `robots.txt` 에서 경로 차단

**1과 2는 함께 적용한다.** sitemap 에는 있는데 `noindex` 인 페이지는
"색인하지 마라" 와 "여기 있다" 가 모순되어 Search Console 경고를 만든다.

## 축 3 — 독창성

**측정**: `content_audit.py` 의 `originality_proxy`

직접 재지 않고 두 대리 지표로 근사한다.

- **경험 신호** — 해봤다, 걸렸다, 재현, 장애처럼 직접 해본 흔적
- **증거 신호** — 단위가 붙은 수치, 버전 번호, 에러 메시지처럼 검증 가능한 구체값

| 등급 | 기준 |
| --- | --- |
| 차단 | 둘 다 없는 글이 30% 초과 |
| 주의 | 10~30% |
| 통과 | 10% 미만 |

**대리 지표는 상한이 아니라 하한을 준다.** 신호가 있다고 독창적인 것은 아니지만,
둘 다 없으면 재서술일 가능성이 높다. 그래서 후보를 좁히는 용도로만 쓴다.

좁혀진 후보는 [`judging.md`](judging.md) 절차로 판정한다.

## 축 4 — 필수 페이지

**측정**: `site_audit.py` 의 `required_pages`

| 등급 | 기준 |
| --- | --- |
| 차단 | 개인정보처리방침이 없거나 200 이 아님 |
| 주의 | 소개·연락처가 없거나, 어느 페이지든 본문 300자 미만 |
| 통과 | 셋 다 있고 각각 실질 내용을 담음 |

개인정보처리방침은 광고 쿠키를 다루므로 사실상 필수다.
**형식만 갖춘 한 줄짜리 페이지는 없는 것과 같게 본다** — 그래서 길이를 함께 잰다.

**측정**: `site_audit.py` 의 `content_root`, `robots.txt`, `sitemap.xml`

| 등급 | 기준 |
| --- | --- |
| 차단 | 사이트 루트가 200 이 아님, `robots.txt` 가 전체 차단, `sitemap.xml` 접근 불가 |
| 주의 | `robots.txt` 에 Sitemap 선언 없음, 응답이 느림 |
| 통과 | 위 항목 없음 |

## 축 6 — 도메인·소유권

**측정**: `site_audit.py` 의 `apply_domain_chain`, `www_variant`, `ads_txt`

| 등급 | 기준 |
| --- | --- |
| 차단 | 신청 도메인 루트에 `ads.txt` 가 없거나 pub-ID 를 담지 않음 |
| 주의 | 신청 도메인이 리디렉션만 반환, `www` 변형이 응답하지 않음 |
| 통과 | 신청 도메인이 직접 콘텐츠를 서빙하고 `ads.txt` 가 유효 |

**리디렉션 구조는 주의로 두되 무겁게 다룬다.**
AdSense 는 루트 도메인 단위로만 신청을 받으므로,
콘텐츠가 서브도메인에 있으면 심사 봇이 처음 보는 것은 리디렉션 응답이다.
봇이 따라간다는 보장이 없어서, 다른 축이 모두 통과인데 계속 떨어진다면 여기를 먼저 의심한다.

## 축 7 — E-E-A-T

**측정**: `metadata_audit.py` 와 소개 페이지 내용

| 등급 | 기준 |
| --- | --- |
| 차단 | 저자를 알 수 있는 정보가 사이트 어디에도 없음 |
| 주의 | JSON-LD 에 `author` 나 `datePublished` 가 없음, 소개 페이지가 익명 |
| 통과 | 구조화 데이터와 화면 양쪽에서 저자와 작성 시점이 드러남 |

익명 블로그보다 저자가 분명한 블로그가 유리하다.
개인 실명까지 필요하지는 않고, 일관된 필명과 이력·연락 경로면 충분하다.

**반드시 렌더된 페이지로 잰다.** 콘텐츠 원본에 작성일과 저자가 없어도
사이트가 DB·커밋 이력·설정값으로 노출하고 있을 수 있다.
`content_audit.py` 의 `metadata` 항목은 원본 frontmatter만 보므로 **판정 근거로 쓰지 않는다.**
그 값은 "원본에 메타가 있는가" 라는 별개 정보이며, 노출 여부와 무관하다.

실제로 이 구분을 놓쳐 오진한 적이 있다.
frontmatter에 작성일이 0개라는 이유로 "메타데이터 없음" 으로 판정했으나,
사이트는 저장된 커밋 날짜를 써서 목록·상세·JSON-LD 모두에 정상 노출하고 있었다.

## 축 8 — 정책 위반

**측정**: 표본 판정. 스크립트로 자동화하지 않는다

| 등급 | 기준 |
| --- | --- |
| 차단 | 저작권 침해 소지 이미지·본문, 금지 주제, 타인 콘텐츠 대량 복제 |
| 주의 | 출처 없는 인용, 외부 이미지 직접 링크 |
| 통과 | 위 항목 없음 |

기술 블로그에서 실제로 걸리는 것은 대부분 **이미지 출처**다.
공식 문서나 블로그의 도표를 출처 없이 옮긴 경우가 흔하다.
`content_audit.py` 대상 글에서 외부 이미지 URL 을 뽑아 표본으로 확인한다.
