# 각 축의 정책 근거

판정 기준이 개인 감각이 아니라 공식 문서에 근거한다는 것을 확인할 수 있게 정리한다.
정책 문구는 개정되므로, 판정이 갈리는 상황에서는 아래 원문을 직접 확인한다.

## 축별 대응

| 축 | 근거 문구 |
| --- | --- |
| 1 콘텐츠 충실도 | "Sites should consist of relevant original content" — 분량 자체보다 독자에게 주는 정보량을 본다 |
| 2 얇은 페이지 색인 | "domains that don't provide valuable information to users" — 판정 단위가 사이트 전체다. 얇은 페이지가 다수면 사이트가 그렇게 보인다 |
| 3 독창성 | "relevant **original** content" — 원본성이 명시된 유일한 축 |
| 4 필수 페이지 | 광고 쿠키 고지 의무. 개인정보처리방침이 사실상 필수인 이유 |
| 5 크롤 가능성 | "landing page quality guidelines" — 심사 봇이 접근하지 못하면 평가 자체가 불가능하다 |
| 6 도메인·소유권 | 신청 시 도메인 소유권과 콘텐츠 편집 권한을 확인하는 절차. 루트 도메인 단위 신청 |
| 7 E-E-A-T | 검색 품질 평가 기준. 승인 심사 문서에 직접 쓰이지는 않지만 저가치 판정과 맞물린다 |
| 8 정책 위반 | 프로그램 정책의 금지 콘텐츠 목록과 저작권 조항 |

## 정책에 없는 것 — 통념과 구분한다

거절 경험담에는 정책 문서에 근거가 없는 기준이 섞여 돈다.
아래는 정책 문서에서 확인되지 않으므로 판정 기준으로 삼지 않는다.

- "글 30개 이상" 같은 고정 개수
- "1,500자 이상" 같은 고정 글자수
- "도메인 3개월 이상" 같은 고정 연령
- 특정 키워드 밀도

이 값들은 관찰된 경향일 수 있으나 공식 요건이 아니다.
[`axes.md`](axes.md) 의 수치도 같은 성격이라 절대 기준이 아니라 판단 보조선으로 쓴다.
경계에 걸린 사이트를 기계적으로 탈락시키지 말고 다른 축과 함께 본다.

## 심사가 사람인가 자동인가

공개된 정보로는 자동 검사와 사람 검토가 함께 쓰인다.
이것이 LLM 채점을 완료 조건으로 쓰면 안 되는 이유이기도 하다 —
판정자를 만족시키는 최적화가 실제 심사와 무관한 방향으로 갈 수 있다.
개선은 판정 점수가 아니라 관측 가능한 사실을 바꾸는 쪽으로 한다.
