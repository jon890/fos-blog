# ADR-037: 학습자료를 공개 글과 분리하고 관리자와 수집기 권한을 나눈다

- **status**: `accepted`
- **결정**: 학습자료는 기존 MySQL의 별도 study 테이블에 저장하고 공개 글 동기화·검색에 포함하지 않는다.
- **소유자와 권한**: 개인 상태의 소유자는 서버가 정한 `owner` 하나다.
  관리자 브라우저 세션과 career-os 서비스 Bearer는 서로 대체할 수 없는 주체로 판정한다.
  관리자 인증은 Better Auth의 GitHub OAuth를 사용하고 환경에 지정한 numeric ID 하나만 허용한다.
  신규 생성과 재로그인 때 같은 기준을 검사하며 계정연결은 허용하지 않는다.
- **맥락**: 공개 글은 GitHub 파일 경로와 활성 상태를 기준으로 동기화한다.
  학습자료는 URL 정규 식별, 기기 간 개인 상태와 추천 이력 보존이 필요하며 수집기가 개인 메모를 고칠 이유가 없다.
- **대안 기각**:
  - 기존 posts에 개인 필드를 추가하면 공개 조회와 동기화 비활성화 정책이 개인 자료에 영향을 준다.
  - 서비스 토큰을 관리자 세션으로 인정하면 수집기가 개인 상태 수정과 가져오기 확정 권한까지 얻는다.
  - 첫 로그인 사용자를 관리자로 지정하면 빈 DB의 최초 접근 순서가 권한을 결정한다.
  - 자체 OAuth·세션 구현은 state·쿠키·세션 철회를 직접 유지해야 하므로 채택하지 않는다.
- **결과**:
  - 얻는 것: 공개 글 회귀를 제한하고 수집기 권한과 본인 계정의 권한을 각각 검사할 수 있다.
  - 감당할 것: 별도 스키마와 인증 검사가 필요하며 다중 사용자는 소유자 모델부터 다시 설계해야 한다.

구체적인 HTTP 권한은 [학습자료 계약](../api/study-library.md#인증-계약), 본인 판정은
[관리자 인증 설정](../code-architecture.md#관리자-인증-허용-계정-판정)에 둔다.
