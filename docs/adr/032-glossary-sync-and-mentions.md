## ADR-032: 콘텐츠 용어집을 동기화하고 언급 페이지를 사전 계산한다

- **결정**: `fos-study/glossary.json`을 용어 정의의 단일 소스로 사용하고, 검증된 정의를 `glossary_terms`에 동기화한다. 글과 카테고리 README의 언급 관계는 콘텐츠 저장 이후 `glossary_mentions`에 계산해 저장한다. Markdown processor singleton은 유지하고 sanitize 이후 요청별 HAST에 용어 노드를 추가한다.
- **맥락**: 용어 변경이 블로그 재배포를 요구하지 않아야 하며, 툴팁과 `/glossary`가 같은 정의를 사용해야 한다. 공개 페이지에서 언급 글을 요청마다 전체 검색하면 응답 비용과 매칭 결과가 불안정해진다. processor에 요청별 plugin 설정을 주입하면 singleton 공유 상태와 동시 요청 안전성이 충돌한다.
- **대안 기각**:
  - `fos-blog` TypeScript 상수는 구현이 단순하지만 용어 변경마다 애플리케이션을 다시 배포해야 한다.
  - 페이지 요청 시 전체 글 검색은 데이터가 늘수록 비용이 증가하고 README까지 일관되게 다루기 어렵다.
  - processor를 용어 목록마다 새로 생성하면 기존 singleton의 초기화 비용 절감과 race 방지 의도를 잃는다.
  - 원본 파일 삭제를 빈 용어집으로 해석하면 실수 한 번으로 모든 툴팁과 역참조가 사라질 수 있다.
- **트레이드오프**: glossary 변경 시 모든 글과 README를 다시 색인하는 비용이 발생한다. 대신 일반 페이지 요청은 저장된 정의와 역참조만 읽으며, 원본 누락이나 검증 실패 시 마지막 정상 데이터를 보존한다. 전체 삭제는 유효한 `terms: []`로만 수행한다.
- **적용 범위**: plan054의 용어 정의 동기화, 본문 최초 등장 툴팁, `/glossary`, 언급 페이지 목록에 적용한다.
