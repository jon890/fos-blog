# ADR-036: 내용이 얇은 카테고리 페이지를 색인에서 제외한다

- **결정**: 카테고리 페이지를 `README` 길이 800바이트 이상이거나 직속 글 5개 이상일 때만 색인 대상으로 삼는다.
  둘 다 미달이면 `sitemap.xml`에서 빼고 페이지에 `robots: { index: false, follow: true }`를 부여한다.
  판정 함수는 한 곳에 두고 sitemap과 페이지가 같은 함수를 쓴다.
  화면은 그대로 렌더하므로 사용자 탐색은 영향을 받지 않는다.
- **맥락**: 카테고리 50개 중 24개의 렌더 본문이 500자 미만이었다.
  글은 사정이 다르다. 같은 기준으로 44개를 검사했을 때 미달이 하나도 없었다.
  저가치 판정의 위험은 글이 아니라 목록 성격 페이지에 몰려 있다.
  검색엔진이 사이트 단위로 품질을 평가하므로 얇은 페이지가 다수면 사이트 전체가 그렇게 보인다.
- **왜 이 두 기준인가**: 카테고리 페이지 본문은 폴더 `README`와 글 목록으로 구성되는데,
  실측상 본문 길이는 `README` 길이에 거의 비례했다.
  글 목록은 제목만 나열해 기여가 작다. 하위 글이 106개인 `devops`도 본문은 717자였다.
  `README`만으로 자르면 목록 자체의 탐색 가치를 놓치므로 직속 글 수를 두 번째 통로로 둔다.
- **왜 800바이트인가**: 임계값별로 제외 대상을 세어 보고 진단 결과와 대조했다.
  800바이트 기준은 23개, 1000바이트 기준은 24개를 제외해 실제 얇은 페이지 24개와 맞물린다.
  둘 중 낮은 쪽을 고른 이유는 경계 사례를 덜 자르기 위해서다.
  색인 제외는 되돌리기 쉽지만 과하게 자르면 탐색 유입이 줄어든다.
  대조 근거는 `README` 1,078바이트인 `devops`가 717자, 600바이트인 `resume`가 245자였다는 실측이다.
- **대안 기각**:
  - **렌더된 본문 길이를 기준으로 사용** 기각 — 가장 정확하지만 sitemap 생성 시점에는 렌더 결과를 알 수 없다.
    별도 집계 경로를 만들어야 하고 그 값이 낡을 여지가 생긴다.
  - **`README`를 보강해 모든 카테고리를 살림** 기각 — 문서 17개를 새로 써야 하고,
    억지로 채운 글은 정보 밀도를 낮춰 오히려 저가치에 가까워진다.
    `README`를 채우면 자동으로 색인에 복귀하므로 두 방법은 배타적이지 않다.
  - **sitemap에서만 제외** 기각 — 내부 링크가 많아 크롤러가 스스로 찾아가 색인할 수 있다.
  - **`follow: false`까지 적용** 기각 — 얇은 카테고리에도 글 링크는 있다.
    크롤러가 글에 도달하는 경로를 막을 이유가 없다. [ADR-005](./005-list-page-noindex.md)가 리스트 페이지에 세운 원칙과 같다.
- **트레이드오프**: 제외된 카테고리는 검색 결과에 노출되지 않아 그 경로의 유입이 사라진다.
  대신 사이트 전체가 얇은 페이지 다수로 평가받는 위험을 줄인다.
  `README`를 채우면 다음 동기화에서 자동으로 복귀하므로 되돌리는 비용은 낮다.
- **적용 범위**: `sitemap.xml`의 카테고리 항목과 `/category/[...path]`의 메타데이터에 적용한다.
  글과 정적 페이지는 대상이 아니다.
  내용이 전혀 없는 카테고리에 이미 적용 중인 `index: false, follow: false`는 그대로 둔다.
