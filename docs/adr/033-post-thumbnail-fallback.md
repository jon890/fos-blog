# ADR-033: 글 전용 썸네일과 카테고리별 생성 이미지를 단계적으로 사용한다

- **결정**: `fos-study`의 상대 `thumbnail` 경로를 동기화 시점에 GitHub raw 절대 URL로 변환해 `posts.thumbnail_url`에 저장한다. 카드는 전용 URL, 카테고리별 `ImageResponse`, `/og-default.png` 순서로 이미지를 선택한다. 글 공유 메타데이터는 전용 URL이 있을 때 이를 우선하고 없으면 기존 글 OG 경로를 유지한다.
- **맥락**: 제목과 발췌만 있는 글 목록은 약 300개 글을 빠르게 구분하기 어렵다. 새 글에는 생성형 이미지를 붙일 수 있지만 기존 글 전체를 즉시 생성하면 비용과 검수 부담이 크다. 요청마다 AI 이미지를 만들면 지연, 비용, 결과 재현성도 보장할 수 없다.
- **대안 기각**:
  - 모든 글의 이미지를 일괄 생성하면 초기 비용과 검수 범위가 지나치게 크다.
  - 카드 요청 때 AI를 호출하면 응답 시간과 운영 비용이 불안정해진다.
  - 하나의 정적 기본 이미지만 사용하면 목록에서 글 사이의 시각적 구분이 다시 약해진다.
  - 카드 조회 때마다 마크다운 본문을 파싱하면 목록 쿼리와 클라이언트 전달량이 커진다.
- **트레이드오프**: 카테고리별 대체 이미지는 같은 카테고리 글 사이에서 반복된다. 대신 기존 글 전체가 즉시 이미지 카드를 얻고, 글 전용 이미지는 콘텐츠 저장소만 갱신해 점진적으로 늘릴 수 있다. 절대 URL은 저장소·브랜치 설정이 바뀌면 전체 동기화가 필요하다.
- **적용 범위**: plan056의 앞표지 동기화, `PostCard`, 글 공유 메타데이터, 카테고리별 대체 이미지 Route Handler에 적용한다.
