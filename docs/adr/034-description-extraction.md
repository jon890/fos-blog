# ADR-034: 글 요약은 산문 블록만 모으고 탐색 안내 인용문은 제외한다

- **결정**: `extractDescription`은 마크다운 본문에서 산문 블록만 모아 요약을 만든다.
  코드 블록, 헤더, 수평선, 표, 이미지는 통째로 제외한다.
  목록과 인용은 줄 머리 마커를 없앤 뒤 내용만 남긴다.
  본문 첫머리의 인용 블록은 그 안에 링크가 있을 때만 제외한다.
  요약 값을 쓰는 화면이 마크다운을 다시 렌더하지 않으므로 마커는 escape 하지 않고 제거한다.
- **맥락**: 기존 구현은 헤더와 인라인 강조만 지우고 줄바꿈을 공백으로 바꿨다.
  그래서 인용과 목록 마커가 문장 한가운데에 남아 `> Agentic GraphRAG에서 이어진다. > 이 글만 Java를…` 같은 요약이 검색 결과와 공유 카드에 노출됐다.
  콘텐츠 저장소 401개 글을 실측한 결과 인용 마커 64건, 수평선 56건이 잔존했다.
  더 큰 문제는 마커가 아니라 뽑히는 문장이었다.
  시리즈 글은 첫머리에 이전 글 안내 인용문을 두는 관행이 있어, 기호를 지워도 글 내용이 아닌 안내문이 요약이 된다.
- **왜 링크 유무로 가르는가**: 첫머리 인용문 43건은 두 성격으로 갈린다.
  다른 글로 보내는 탐색 안내문 36건은 요약 가치가 없다.
  `"Remote Dictionary Server" — 원격에 위치한 프로세스로 동작하는 인메모리 키-값 데이터 구조 서버` 같은 정의문 7건은 오히려 요약으로 가장 적합하다.
  탐색 안내문은 대상 글을 가리켜야 하므로 링크를 담고 정의문은 담지 않는다.
  이 신호가 실측 43건을 36 대 7 로 정확히 갈랐다.
- **대안 기각**:
  - 마커를 escape 하면 요약이 마크다운으로 렌더되지 않으므로 backslash가 화면에 그대로 노출된다.
  - 첫머리 인용을 전부 제외하면 정의문 7건이 요약에서 사라져 글의 핵심 정의를 잃는다.
  - "이어진다", "관련 문서" 같은 문구 목록으로 가르는 방식은 글쓴이의 표현이 바뀔 때마다 깨진다.
  - 콘텐츠 저장소의 마크다운 원본을 고치는 방식은 ADR-010이 정한 방침과 어긋나고 글이 늘 때마다 반복된다.
- **트레이드오프**: 정의문에 링크를 달면 탐색 안내문으로 오인해 제외한다.
  글쓴이가 첫머리 인용문의 링크 유무로 의도를 표현할 수 있으므로 규칙을 아는 상태에서는 제어 가능하다.
- **저장 값 보정**: 목록 카드와 RSS는 `posts.description`에 저장된 값을 쓰는데, 동기화는 파일 `sha`가 같으면 건너뛰므로 함수만 고치면 옛 값이 남는다.
  ADR-010 이후 제목을 매 동기화마다 재계산해 보정하던 경로에 요약 보정을 합쳐, 저장된 본문에서 두 값을 한 번의 순회로 다시 계산한다.
  본문을 두 번 읽지 않으려고 순회를 합쳤고, 값이 달라진 글만 갱신하므로 최초 1회 이후에는 쓰기가 발생하지 않는다.
