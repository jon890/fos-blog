# ADR의 전체 범위와 phase의 열거 범위가 어긋남

## 관찰

ADR-034는 코드 블록, 헤더, 표를 통째로 제외한다고 결정했다.
그러나 phase와 구현은 코드 펜스, ATX 헤더, 선두 `|`가 있는 표만 다뤘다.

문서 정합성 검증에서 Setext 헤더, 들여쓰기 코드, 선두 `|`가 없는 GFM 표가 요약에 노출됨을 재현했다.

## 원인

phase가 구현 규칙을 구체화하는 과정에서 ADR의 상위 범주를 일부 문법만으로 축소했다.
critic과 코드 검토는 phase 충족 여부를 중심으로 확인해 상위 결정과의 범위 차이를 놓쳤다.

## 영향

일부 마크다운 문법이 검색 설명과 공유 미리보기에 평문으로 노출될 수 있다.
task를 충족한 구현이 ADR을 위반하는 상태로 완료될 뻔했다.

## 대응

코드가 ADR의 상위 범위를 충족하도록 GFM 구문 트리 기반 회귀 테스트와 구현을 추가한다.
관련 관리 문서를 갱신하되, 완료된 task는 당시 실행 계약으로 보존한다.

## 검증

대상 테스트 91개와 문서 정합성 재검증이 통과했다.

## 배운 점

phase가 ADR의 일반 범주를 구체 문법으로 열거할 때는 그 열거가 전체 범위를 보존하는지 별도로 대조해야 한다.

## 후속

같은 유형이 반복되면 critic 점검 규칙 승격을 검토한다.

## 해결 결과

`remark-parse`와 `remark-gfm`이 판정한 `heading`, `code`, `thematicBreak`, `table` 블록 전체를 요약에서 제외했다.
문단과 목록의 들여쓰기 산문은 보존하고, 여러 줄 Setext 헤더는 전체를 제외하는 회귀를 추가했다.

code-reviewer는 `PASS`를, docs-verifier는 코드와 관리 문서의 위반 해소를 확인했다.
이번 사건은 첫 관측이라 공용 함정으로 승격하지 않는다.
