# 색인 정책 계획이 경로 정규화와 메타데이터 회귀를 닫지 못함

## 관찰

최초 phase는 sitemap과 카테고리 페이지가 같은 판정 함수를 쓰도록 했지만,
판정 입력을 만드는 경로 정규화와 직속 글 계산 기준을 구체적으로 닫지 않았다.
또한 페이지의 `robots` 반환값을 실제로 검증하는 테스트가 없었다.

## 원인

순수 판정 함수의 테스트가 두 호출처의 입력 계산과 출력 메타데이터까지 보장한다고 넓게 해석했다.

## 영향

구현자가 대소문자가 다른 경로를 서로 다른 키로 취급하거나,
교차 카테고리 글을 직속 글로 세면 ADR-036의 임계 판정이 달라질 수 있었다.
`page.tsx`가 `follow: true`를 놓쳐도 기존 검증은 통과할 수 있었다.

## 대응

phase에 다음을 추가했다.

- README 길이와 직속 글 수를 소문자 경로로 조회하는 계약
- 직속 글 수는 `posts.length`로 계산하고 `mergedPosts.length`를 제외하는 계약
- `FolderRepository` 매핑과 `generateMetadata` robots 결과를 직접 검증하는 회귀 테스트

## 검증

수정한 phase를 critic에게 다시 평가하도록 요청했다.

## 배운 점

공용 정책 함수는 결과 판정의 일관성만 보장한다.
호출처별 입력 계산과 출력 계약은 각 경계의 테스트로 따로 고정해야 한다.

## 후속

이번 phase 구현과 누적 검토에서 추가 누락이 없는지 확인한다.
