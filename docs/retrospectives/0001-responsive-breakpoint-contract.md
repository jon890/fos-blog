# 반응형 용어와 실제 분기점 불일치

## 관찰

계획은 모바일 1열, 태블릿 2열, 넓은 화면 3열을 요구했다.
구현은 `md:grid-cols-2 lg:grid-cols-3`를 사용해 1024px에서 이미 3열로 전환됐다.
독립 코드 검토자가 1024×768 브라우저 측정으로 불일치를 발견했다.

## 원인

`lg`를 넓은 화면이라는 자연어 표현에 바로 대응시켰다.
검증 화면 크기별 기대 열 수를 계획과 테스트에 명시하지 않아 Tailwind 분기점의 실제 경계를 놓쳤다.

## 영향

태블릿 가로 화면에서 카드 폭과 제목 가독성이 계획보다 일찍 줄어든다.
홈, 최신 글, 카테고리, 태그, 시리즈, 관련 글과 로딩 상태가 같은 문제를 공유한다.

## 대응

3열 전환점을 `xl`로 늦추고 모든 격자와 로딩 상태에 같은 기준을 적용한다.
1024px는 2열, 1440px는 3열이라는 브라우저 검증 결과를 남긴다.

## 검증

- 모든 글 격자와 로딩 상태의 3열 분기점을 `xl`로 통일했다.
- 회귀 테스트가 `md:grid-cols-2`, `xl:grid-cols-3` 계약을 고정한다.
- Orca에서 `/posts/latest`를 측정한 결과 1024×768은 2열, 1440×900은 3열이었다.
- 두 화면 모두 가로 넘침이 없었다.

## 배운 점

반응형 요구사항은 모바일·태블릿·넓은 화면 같은 용어만으로 닫히지 않는다.
검증 화면 크기마다 기대 열 수를 함께 적어야 구현 분기점과 동일한 계약이 된다.

## 후속

분기점 수치를 `docs/design.md`, `docs/prd.md`, phase 검증 조건에 기록했다.
현재 계획과 테스트가 재발을 막으므로 별도 공용 지침으로 승격하지 않는다.
