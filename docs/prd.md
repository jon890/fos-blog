# PRD — 최신/인기 글 목록 페이지 (무한 스크롤)

**작성일:** 2026-04-19
**상태:** 구현 완료
**관련 pages PRD:** [posts-latest](./pages/posts-latest.md) · [posts-popular](./pages/posts-popular.md) · [home](./pages/home.md)

---

## 1. 문제 정의

기능 도입 전에는 홈페이지에서 인기 글과 최근 글을 각각 6개만 노출했다.
방문자가 전체 글을 최신순이나 인기순으로 훑어볼 수 있는 경로가 없었다.
현재는 전용 목록 경로를 제공해 이 탐색 공백을 해소한다.

현재 전체 글 수는 약 200개 — 홈의 6개는 전체의 3%에 불과하다.

---

## 2. 목표

- 방문자가 전체 글을 **최신순 / 인기순으로 연속 탐색**할 수 있는 전용 페이지 제공
- **SEO 손해 없이** (첫 10개 SSR) + **스크롤 UX** (이후 무한 로드)
- 200개 규모에서 **빠른 응답** (p95 < 300ms per page fetch)
- **접근성**: 키보드 / 스크린리더 사용자도 동일하게 탐색 가능 (수동 "더 보기" 버튼 병행)

---

## 3. 범위

### In Scope
- 최신 글 목록 페이지 `/posts/latest` (cursor 기반 무한 스크롤)
- 인기 글 목록 페이지 `/posts/popular` (offset 기반 무한 스크롤)
- 홈페이지 두 섹션 하단에 **"최신 글 더 보기 / 인기 글 더 보기"** CTA 버튼
- Repository 신규 메서드 2개 + API Route 2개
- DB 인덱스 2개 추가 (정렬 성능)

### Out of Scope
- 카테고리별 무한 스크롤 (`/category/*`) — 글 수가 적어 기존 정적 방식 유지
- URL에 페이지 상태 반영 (`?page=N`) — Q8 결정: 스크롤 위치만 복원
- sessionStorage 기반 뒤로가기 시 로드된 목록 복원 — Q14 결정: 단순하게 가고 추후 추가 구현 여지
- 필터 (카테고리/기간) — 이번 범위 아님

## 5. 로딩 / 끝 도달 UX

| 상태 | 처리 |
|---|---|
| 로딩 중 (추가 fetch) | PostCard 스켈레톤 3개 |
| 추가 로드 실패 | 인라인 "재시도" 버튼 (같은 cursor/offset 재시도) |
| 끝 도달 (인기/최신 공통) | "더 이상 글이 없습니다." 문구 + "맨 위로" 버튼 |
| 스크롤 300px 이상 | 플로팅 "맨 위로" 버튼 노출 |

---

## 6. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| SSR 첫 페이지 p95 | < 300ms |
| 추가 fetch p95 | < 300ms |
| ISR | 최신=60초, 인기=600초(10분) |
| 신규 의존성 | 0개 (IntersectionObserver 직접 구현) |
| SEO | `robots: { index: false }` — 리스트는 색인 제외 |
| 접근성 | `aria-live="polite"` 로딩 상태 안내, "더 보기" 버튼 키보드 조작 가능 |

---

## 7. 수용 기준 (Acceptance Criteria)

1. 홈페이지 "최신 글" / "인기 글" 섹션 하단에 CTA 버튼 표시 — 클릭 시 `/posts/latest` / `/posts/popular` 이동
2. `/posts/latest` 진입 시 SSR로 최신 10개 렌더 (`updatedAt DESC, id DESC` 정렬)
3. `/posts/popular` 진입 시 SSR로 인기 10개 렌더 (`visitCount DESC, pagePath ASC` 정렬, `visitStats` 등록된 글만)
4. 스크롤 바닥 근처 도달 시 다음 10개 자동 로드 — 스켈레톤 3개 노출
5. "더 보기" 버튼으로도 동일 동작 (키보드만 사용 가능)
6. 끝 도달 시 "더 이상 글이 없습니다." + "맨 위로" 버튼
7. 추가 fetch 실패 시 인라인 "재시도" 버튼, 클릭 시 동일 cursor/offset 재요청
8. 두 페이지 모두 PostCard에 `visitCount` 함께 표시 (홈 "최근 글"과 일관성)
9. `meta robots = noindex`
10. Repository 신규 메서드 단위 테스트 + API Route 통합 테스트 통과

## 글 카드 대표 이미지 (plan056)

### 문제

글 목록이 제목과 짧은 설명만 보여 주어 긴 목록에서 글마다 시각적 구분이 약하다.
기존 글은 약 300개라 모든 글에 전용 이미지를 한 번에 만드는 방식도 현실적이지 않다.

### 목표

- `fos-study` 글의 `thumbnail` 앞표지 값을 동기화해 카드와 공유 메타데이터에 사용한다.
- 전용 이미지가 없는 기존 글에는 카테고리별 생성 이미지를 표시한다.
- 이미지가 깨져도 사이트 기본 이미지까지 단계적으로 대체한다.
- 목록의 제목, 카테고리, 날짜 정보는 이미지와 함께 유지한다.

### 수용 기준

1. `thumbnail`이 있는 글은 홈, 최신·인기, 카테고리, 태그, 시리즈, 관련 글 카드에서 전용 이미지를 표시한다.
2. `thumbnail`이 없는 글은 카테고리별 생성 이미지를 표시한다.
3. 전용 이미지 로드가 실패하면 카테고리별 생성 이미지로 바꾸고, 이 경로도 실패하면 `/og-default.png`를 사용한다.
4. 카드 이미지는 16:9 비율을 유지하고 제목은 접근 가능한 HTML 텍스트로 표시한다.
5. 전용 썸네일이 있으면 글의 Open Graph와 X 카드도 같은 이미지를 사용한다.
6. `thumbnail`이 없으면 기존 `/api/og/posts/[...slug]` 공유 이미지를 유지한다.
7. 이미지에는 빈 대체 텍스트를 사용하고 인접 제목을 접근 가능한 이름으로 유지한다.

## 썸네일 중심 글 탐색 (plan057)

### 문제

글 목록이 제목과 소개글을 읽어야만 글 사이의 차이를 판단할 수 있다.
글 수와 전용 썸네일이 늘어났지만 작은 행 이미지에서는 대표 이미지의 발견 효과가 제한된다.

### 목표

- 홈 최근 글, 최신 글, 카테고리, 태그, 시리즈, 관련 글을 썸네일 중심 카드로 통일한다.
- 이미지를 먼저 보고 제목으로 클릭 여부를 확정할 수 있게 한다.
- 일반 카드는 이미지와 제목 영역을 분리해 긴 기술 제목의 가독성을 보존한다.
- 홈 최근 글의 첫 항목만 제목을 이미지 위에 표시하는 대표 카드로 강조한다.
- 인기 글은 순위와 조회수를 빠르게 비교할 수 있도록 기존 행 목록을 유지한다.

### 범위 제외

- 이미지 파일 자체에 제목을 합성하지 않는다.
- 검색 결과와 인기 글을 카드 배열로 바꾸지 않는다.
- 썸네일 동기화, 데이터베이스, API 응답 계약을 변경하지 않는다.
- 목록 노출이나 클릭을 위한 새 분석 이벤트를 추가하지 않는다.

### 수용 기준

1. 일반 카드는 16:9 이미지, 분류·날짜, 최대 두 줄 제목, 선택적 조회수를 표시한다.
2. 일반 카드에서 소개글을 표시하지 않는다.
3. 홈 최근 글의 첫 항목은 전체 열을 차지하는 대표 카드이며 제목을 이미지 위의 어두운 덮개에 최대 세 줄로 표시한다.
4. 카드 배열은 모바일 1열, 768px 이상 2열, 1280px 이상 3열로 반응한다.
   1024px 태블릿 가로 화면은 2열을 유지한다.
5. 최신 글의 초기 항목과 추가 로드 항목은 같은 카드 배열에 누적된다.
6. 인기 글의 홈과 전용 페이지는 기존 행 목록과 행형 로딩 상태를 유지한다.
7. 이미지 오류와 빈 목록, 추가 로드 실패 흐름은 plan056과 기존 무한 목록 계약을 유지한다.
8. 키보드 초점, 모션 감소, 카드 링크의 접근 가능한 글 제목을 유지한다.

## 용어집과 본문 설명 툴팁 (plan054)

### 문제

전문 용어가 별도 설명 없이 본문에 등장해, 독자가 문맥을 벗어나 검색해야 한다.
같은 용어의 설명과 실제 사용 글을 함께 탐색할 경로도 없다.

### MVP 범위

- `fos-study/glossary.json`을 용어 정의의 단일 소스로 사용한다.
- 글과 카테고리 README에서 개념별 첫 등장에 설명 툴팁을 표시한다.
- 제목, 링크, 코드, 수식, Mermaid 내부는 자동 감지하지 않는다.
- `/glossary`에서 용어 검색, 가나다·알파벳 탐색, 상세 설명, 참고 자료를 제공한다.
- 각 용어가 언급된 글과 카테고리 README를 표시한다.
- Footer와 본문 툴팁에서 용어집으로 진입하며 Header에는 추가하지 않는다.

### 범위 외

- 별도 용어 상세 라우트
- 용어집 웹 편집 화면
- 글 작성자가 매칭 위치를 직접 지정하는 전용 Markdown 문법
- 런타임 전체 본문 검색
